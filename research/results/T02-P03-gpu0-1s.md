## Interpretation

The SASS inspection already showed `IDP.4A.S8.S8`; this run establishes that
the executed packed-int8 path produces the exact expected output on the P40.
Its 179.637 GOP/s should not be compared to a large-GEMM TOPS specification:
the current kernel is a 512-block GEMV with only two DP4A iterations per thread,
per-output reduction overhead, repeated input loads, and only about 1 MiB of
weights per GEMV. It is a correctness/thermal baseline, not a candidate final
kernel.

The important falsifiable next question is whether a tiled, input-reuse-aware
DP4A layout can materially increase useful operations per byte without harming
the numerical contract. That requires a separately reviewed benchmark variant,
not a claim based on this result.

## Next gate

Keep the current fixed P03 profile as the control. Design an isolated, bounded

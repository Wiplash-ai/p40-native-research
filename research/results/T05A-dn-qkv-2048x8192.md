# T05A — cached Q8 DeltaNet `dn_qkv` GPU control

Date: 2026-09-08. Status: **numerical and GPU-latency pass; CPU/GPU ratio
requires the cache-aware follow-up**. This proves that the cached GPU path
correctly executes one Qwen-shaped DeltaNet Q8-weight, FP32-activation
projection at the recorded latency. It does not yet prove a profitable CPU/GPU
comparison or an end-to-end Qwen gain.

The control used synthetic, deterministic data but exactly the storage and
operator form used by Qwen's normal x86 dense path: per-output-scale int8
weights and FP32 activations. Its CPU reference uses Qwen's AVX2/FMA
accumulator structure. The GPU test calls the existing cached
`coli_cuda_matmul()` format-1 API on one P40 at 125 W. A fresh first call
includes CUDA initialization and upload; every timed steady-state call retains
the Q8 weights on device and includes activation H2D, kernel execution,
result D2H, and synchronization.

| Shape | 2048 input x 8192 output |
| Cached Q8 weight bytes | 16,809,984 |
| First GPU call, including initialization/upload | 21.228 ms |
| CPU samples, ms/call | 5.015, 4.921, 4.394, 4.645, 4.634 |

| GPU complete median | 0.335 ms/call |
| Observed CPU/GPU ratio | **13.86x** (not promotable; see correction) |

| Maximum relative error | 5.965e-6 |
| Numerical gate | pass |

The declared tolerance was `abs_error <= 1e-4 + 1e-4 * abs(reference)` for
every output. The GPU output passed it. The generic backend does not expose
separate H2D/kernel/D2H events for this API, so this record intentionally
reports the synchronous complete call rather than inventing a per-stage split.

## Safety

Two preflight snapshots were idle and stable at 35 C / 37 C, with 0 MiB on
both GPUs and all eight fans at 2,000–2,100 RPM. The guard sampled a 36 C peak
on GPU0 and 37 C on GPU1, saw no fresh fan/device fault, released the CUDA
process, held a five-minute minimum cooldown, and restored GPU0 from 125 W to
its original 250 W cap. The work phase completed between telemetry polls, so
the fixture's own cached-tensor accounting—not sampled VRAM—is the evidence
that 16.0 MiB of weight plus 32 KiB of scales was resident during timing.

## Measurement correction and decision

The GPU latency and numerical result stand. However, T05B revealed that this
first fixture inherited its caller's OpenMP settings and timed the same 16 MiB
projection repeatedly. That is not a faithful CPU control for Qwen's 30
DeltaNet layers: the synthetic weight can become cache-hot and the CPU thread
policy was not pinned to Qwen's 24-thread policy. Consequently, the 13.86x
ratio must not be used to clear the project's 15% keep threshold.

The guard now launches fixtures with the fixed Qwen OpenMP environment. T05C
will use the same three projections across all 30 virtual DeltaNet layers
(about 960 MB Q8 weight), exceeding either socket's 60 MiB L3 cache and
matching Qwen's per-token projection working set. Do not tune the generic
kernel or wire it into Qwen until that control produces a stable comparison.
